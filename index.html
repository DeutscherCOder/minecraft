Ready to slip out of reality..?

Ein idempotenter Installer, der Minecraft 1.20.1 + Fabric sowie 7 Mods einrichtet — manifest-basiert über config/mods.json. Gleicher Befehl, zehnmal ausgeführt, kein Chaos.

PowerShell öffnen (Win + R → „powershell“) und das hier einfügen: 
Set-ExecutionPolicy -Scope Process Bypass -Force; $i="$env:TEMP\dreamshift.zip"; Invoke-WebRequest -Uri 'https://github.com/DeutscherCOder/minecraft/archive/refs/heads/main.zip' -OutFile $i; Expand-Archive -Path $i -DestinationPath "$env:TEMP\dreamshift" -Force; & "$env:TEMP\dreamshift\minecraft-main\install.ps1"

Alternativ ohne Konsole: Repo als ZIP laden → entpacken → install.ps1 mit „Rechtsklick → Mit PowerShell ausführen“.

Der Befehl ist idempotent — beliebig oft ausführbar, es wird nie doppelt verschoben.

So arbeitet der Installer

  1. 01
    Minecraft finden. Standard: %APPDATA%\.minecraft. Für Tests: -GameDir "…".
  2. 02
    Java prüfen (≥ 17). Fehlt es, versucht das Script winget install Oracle.JDK.17.
  3. 03
    Fabric CLI-Installer laden und per SHA-1/SHA-512 verifizieren.
  4. 04
    Fabric Loader installieren — komplett ohne GUI, idempotent.
  5. 05
    mods/ analysieren — jede .jar wird nach config/mods.json eingestuft.
  6. 06
    Ergebnis: Behalten / Backup (Zeitstempel) / Download. Fertig.

    Mod hinzufügen / Version ändern

    Alles steckt in zwei Dateien — keine Logik im Weg:

    • config/mods.json — Mods, exakte Versionen, URLs, SHA-1/SHA-512, Dateinamen-Muster (match).
    • config/installer.json — Minecraft-Version, Loader-Version, Fabric-Installer mit Prüfsummen.
    • install.ps1 — konsumiert nur diese Manifeste (Regeln: Behalten / Backup / Download).
    • tests/test-offline.ps1 — Offline-Selbsttest; .github/workflows/selftest.yml — echter Windows-Selbsttest per GitHub Actions.

    Bei einer neuen Version einfach die Modrinth-Versions-API abfragen und URL+Hashes austauschen — der Rest bleibt identisch und idempotent.
